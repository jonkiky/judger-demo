# 文书模板与材料阅读工作流

文书起草、补充要求、继续修改、正文编辑、复核与下载都在案件的「文书草稿」页进行。任务记录仅显示状态、错误和执行详情，文书任务链接返回文书页。

## 使用方式

1. 选择文书类型，以及内置模板或材料中心的模板文件。也可直接上传 DOCX、文本型 PDF、TXT 或 Markdown 模板；上传后以「文书模板」保存到材料中心。
2. 选择作为事实参考的本案材料。模板不会作为本案事实送入材料阅读范围。可为每份材料补充阅读重点，例如付款金额与日期、交付条款或通知内容。
3. 填写本轮起草要求。所有选择、模板内容和版本、材料哈希、阅读重点与要求固定在任务快照中。
4. 各份材料分别阅读，页面展示逐份进展与可核对的发现。所有阅读任务成功后才开始统筹生成；任何一份失败都不交付不完整文书。恢复原任务复用成功的阅读报告，只重试失败材料。
5. 文书完成后在当前页面审阅。点击段落来源编号可打开原文并高亮引用，来源索引保存文件名称、版本、位置、引用文本与字符区间。
6. 可直接修改正文，或填写「修改要求」继续生成。两种方式都保存新版本、保留旧版并重置复核状态。生成中的旧版如果已被另一页面修改，拒绝覆盖。
7. 每个通过程序检查的新版本自动保存为 Word，并出现在材料中心的「文书与研究文档」。Word 草稿可在人工复核前下载；复核后仍可导出 Markdown。文件附来源与版本信息。

## 模板格式

- 内置模板提供民事起诉状、代理意见、客户情况说明与内部研究报告的固定章节。
- 上传模板优先使用 `{{填写项}}` 作为章节/填写位置；否则使用 Word 标题样式、Markdown `##` / `###` 标题，或「一、…」等编号标题。没有可识别标题时，将完整模板作为「正文」填写要求，不截断模板。
- DOCX 的命名填写项保留原段落、表格、样式与页面设置；填写项可跨多个 Word run。人工编辑保留这些章节时继续填入原布局。若人工改了整体结构，则以编辑后的正文为准，保留模板样式与页面设置并重新排列正文。
- 其他模板按章节和内容要求起草，PDF 不承诺还原页面版式。模板最多 7,000 字、12 个章节。模板中的示例身份、金额等不能作为本案事实。

## 执行与来源

`document_agents.py` 为每份材料创建独立阅读任务，最多两个请求同时在途。长材料按确切字符区间分片，不省略文件尾部。模型只选择服务器生成的来源 ID，不能自行改写引用。阅读报告按模板章节组织，包含发现、来源 ID、未见信息、读取字数和完成状态，保存在 `document_agents` 表中。

统筹步骤等待全部报告，并逐模板章节生成正文。每节输入包含所有材料的对应发现与原文引用。未知 ID、跨材料引用、缺失段落来源、无来源法条编号和超出上下文预算均阻止交付。没有材料支持的章节直接保留「待补充」。程序校验不代表已经核实事实真实性或法律推论，仍需逐段人工复核。

单次材料上限沿用 20 份 / 60,000 字。文书任务最多 100 次模型调用、3,600 秒活跃执行时间；每次模型输入仍受现有 15,000 字符限制，材料报告过大时明确报错并要求缩小范围，不静默截断。

Word 文件保存在既有 `reference_documents` 存储，不作为新的事实材料，因此不会使刚生成的文书过期、取消正在运行的任务或造成递归引用。撤回任一输入材料或模板会停止展示相关文书及下载文件；撤回材料也会隐藏其阅读报告。

## API

- `GET /api/v1/document-templates`：已登录用户读取内置模板。
- `POST /api/v1/cases/{cid}/requests`：沿用认证、CSRF、幂等键、案件权限及任务预算。`workflow: document.generate` 直接读取本案材料，不要求跳转选案。增加 `document_template_id`（`builtin:complaint` 等或本案材料 ID）、`document_tasks`（材料 ID 到阅读重点的映射）。`goal` 为起草/修改要求。
- 继续修改时传 `document_artifact_id` 与 `document_content_hash`。模板默认继承原版；原版本已过期、已存在子版本或正在修改时返回 409。
- `GET /api/v1/runs/{rid}/document`：带案件权限检查的逐材料进展与来源报告。
- `POST /api/v1/artifacts/{aid}/versions`：沿用 `body`、`content_hash`，保存后自动归档 Word。
- `GET /api/v1/reference-documents/{did}/download`：下载对应的不可变 Word 文件；重新校验来源撤回和内容阻止状态。新归档条目包含 `kind: document` 和当前 `review_status`。

## 验证

```sh
.venv/bin/python -m pytest tests/test_documents_workspace.py -q
npm --prefix frontend run build
node scripts/browser_documents_workspace_test.cjs
.venv/bin/python scripts/document_live_check.py
```

单元与 API 测试使用隔离存储和确定性模型输出，覆盖材料隔离、等待全部响应、失败恢复、未知引用、模板权限、撤回、并发版本冲突、Word 表格填写及人工编辑保留表格。浏览器测试启动临时 API，并用真实工作流配合确定性模型响应，覆盖模板上传、阅读重点、停留文书页、刷新恢复、来源高亮、编辑、生成新版本、下载、材料中心跳转、任务记录只读与手机宽度。

真实模型验收脚本使用独立临时案件库，只连接既有本机模型网关；不会写入用户案件。结果与 Word 样本保存在 `evaluation/document-workspace`。Word 视觉验收使用捆绑的 LibreOffice 渲染器；本机渲染需要可读的中文字体及可写 Fontconfig 缓存。真实模型测试证明流程完成与来源解析，不能替代文书内容的法律审核。
