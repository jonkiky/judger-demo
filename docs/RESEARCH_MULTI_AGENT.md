# 结果与研究

更新：2026-11-07。研究协议：`research-top5-v1`。

## 使用流程

「结果与研究」以连续对话为主区域，首问和追问共用一个消息输入框；右侧展示「逐案研究」、任务状态和来源。手机端将过程与来源排列在聊天下方。「类案」和「本次材料范围」各选择 1–3 项。类案来自本案「类案」页当前保留的有效结果，默认勾选前三个不同案件；材料默认前三份可读文件，排除文书模板。任一区域选满三项后禁用其他未选项，取消后可更换，原文随时可核对。空白对话提供类案对比、诉讼策略、证据与补证、风险与抗辩、诉讼请求梳理、研究摘要六种提示词，选择只填入消息，不自动发送。Enter 发送、Shift + Enter 换行，输入法选字不触发发送。请求失败、来源核对和轮询均保留未发送消息。新对话通过 `?new=1` 明确开始，不展示另一轮旧报告。

页面将 `research_selection`（列表版本与所选文书 ID）和 `material_ids` 一并提交。API 检查来源上限、重复、权限、可读性、列表版本、移出记录和语料版本；过期列表需重新分析。所选范围固定到本轮快照，不修改案件全局选案，不因后续列表变化而扩大。类案或材料为空时不能开始研究。兼容旧 API 调用的默认检索与历史任务恢复；历史已固定的五案范围仍可按原输入恢复。

聊天右上角提供「全屏／还原」与来源侧栏开关。全屏占满应用可视区域，默认把过程与来源收成右侧窄栏，仍可展开核对；退出全屏恢复原布局。Esc 先关闭打开的原文，再退出全屏，输入法选字期间不触发退出。聊天、草稿和选案始终保留在原组件中，不因布局切换重新加载。左右侧栏折叠偏好仅保存于本机浏览器，独立于案件数据；全屏中的临时折叠状态不覆盖普通布局偏好。手机端全屏展开来源时显示侧面板，正常页面仍将来源排在聊天下方。顶部导航压缩到 48px，左侧导航可从顶部按钮切为图标栏，手机保留原菜单。

主界面不再展示历史「请继续本轮研究」卡片，也不重复展示文书任务；从任务记录进入指定研究会话后，仍可处理该任务的待选择内容、取消或恢复。文书任务在文书草稿中处理。

每个类案独立调用模型，只接收该案的元数据和精确原文片段。复用证据分析的原文定位、覆盖范围标记、来源校验、模型调用缓存和两个在途请求限制。所有逐案响应成功后，统筹模型结合完整逐案报告、本案材料及法源快照形成最终研究。程序检查每个选定案件均被引用，失败时保留已完成的逐案结果，重试只执行未完成部分。

统筹输出出现法条引用错配或无来源案号时，最多对两段执行有原文约束的引用修复；每段首次修复仍不通过时，最多再调用一次模型，要求保留有依据内容、以来源 ID 表达法源而不猜测条号，并再次执行同样的校验。修复上下文保留该段提及的已选类案、本案材料与相关法源，避免只带法条后误将合法类案判为外部案号。修复调用键使用 `citation_repair:v2`，可恢复旧综合输出而不与旧修复请求冲突。案号统一处理全角字符、括号和空白；所引原文中明确记载的本案或原审案号可引用，未知案号仍阻止保存并显示具体号码；遗漏案例时，只执行一次补充比较请求，并在响应结构中明确要求每个遗漏案例。修复仍须通过原有法条、来源和全案覆盖检查，不由程序猜测或自动补贴引用。每次修复有独立模型操作键，可恢复及审计。

同一个聊天输入框在已有报告时固定用户正在查看的研究版本和来源，结合最近问答完善完整报告。每次成功创建新版本，保留父版本和全部对话；历史版本可切换查看。父报告失效、来源撤回或资料范围变化时拒绝继续使用。历史任务链接会显示其后续完善版本。

「保存 Word 到材料中心」归档当前报告、逐案分析、追问记录和来源索引。「下载 Word 供审阅」直接下载，不额外归档。材料中心支持下载及确认删除，删除不会删除研究报告、对话或上传材料；删除后的下载地址返回 404，重复旧保存请求不会恢复已删除文件。

## 实现与 API

证据分析、自动研究和文书或任务中的选案步骤共用 `DEFAULT_CASE_ANALYSIS_COUNT = 3`。检索仍返回完整候选，按案号去重后取默认范围；已有手动选择及历史任务的已固定范围按其原范围继续。

- `research_agents.py`：持久逐案执行、全部响应屏障、统筹、失败恢复。
- `research_workspace.py`：有来源的追问和原子保存新版本。
- `research_documents.py`：可编辑 Word 报告。
- `ResearchPanel.tsx`：连续聊天、单一输入框、右侧逐案进度、固定来源、报告版本和导出。
- `ResearchSetup.tsx`：两类来源选择、三项上限、提示词与本轮范围状态。
- `ReferenceDocuments.tsx`：证据与研究共用的归档列表和删除控件。
- `research_batches` / `research_agents`：批次和逐案状态，与证据分析互不覆盖。

```text
PUT    /api/v1/cases/{cid}/research-selections       {doc_ids: [最多5项]}（保留的旧接口）
POST   /api/v1/cases/{cid}/requests                 {workflow: "case.assess", goal: "...", material_ids: [1至3项], research_selection: {similar_version: 1, doc_ids: [1至3项]}}
GET    /api/v1/runs/{rid}/research
POST   /api/v1/runs/{rid}/retry
POST   /api/v1/cases/{cid}/requests                 {workflow: "research.followup", research_artifact_id: "...", goal: "..."}
POST   /api/v1/artifacts/{aid}/reference-documents   {content_hash: "...", save_to_materials: true/false, timezone: "..."}
GET    /api/v1/reference-documents/{did}/download
DELETE /api/v1/reference-documents/{did}
```

沿用会话、CSRF、案件授权、请求幂等和精确来源校验。新研究默认最多 32 次模型调用与 1,800 秒活跃阶段预算；同时包含证据与研究的任务为 48 次模型调用。Word 是待审阅参考文档，不要求先将 AI 内容标为人工复核通过。

```sh
npm --prefix frontend run build
```

隔离测试使用受控模型响应，覆盖默认三个及历史五个独立调用、汇总顺序、失败恢复、遗漏案例拒绝、重复案号、权限、追问新版本、Word 内容与下载/删除生命周期。新增范围测试覆盖每类最多三项、不可读材料、列表版本冲突、已移出类案、语料变化、幂等与固定来源，验证显式选择不会回退到未选来源。程序与浏览器通过不代表法律内容已经人工审核。

浏览器验收：`node scripts/browser_research_workspace_test.cjs`。使用隔离 API 与测试进度，不调用模型；覆盖单输入框、右侧过程、首问与追问、失败恢复、输入法选字、草稿保留、历史版本、新对话隔离与手机布局。
